# Documentation Guidelines

## Keep documentation current

Maintain a clear `README.md` for the project and update it when behavior, setup, or workflows change.

Use the repository's existing conventions for:

- setup
- environment variables
- scripts
- test commands
- deployment notes
- API usage
- troubleshooting

## README expectations

A good project README should answer:

- what the project does
- how to install it
- how to run it locally
- how to test it
- how to configure required environment values
- how the public API or interfaces work
- where to find more details for contributors

## Comments

Comments should explain intent, assumptions, or constraints that are not obvious from the code.

Do not use comments as a substitute for clear naming or clean code.

Remove stale comments and commented-out code before finishing a change.

## Cross-references

If a project relies on a discussion, design decision, external article, or specific API behavior, document the relevant link or note when it is useful to future maintainers.

Keep comments and docs relevant as the code evolves.
